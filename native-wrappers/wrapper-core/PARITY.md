# Native client parity review

The authoritative `parity.json` ledger records native Rust → wrapper-core and
wrapper-core → C decisions separately. The unpublished repository audit checks
qualified declarations, mapping targets, restrictions, evidence references and
these generated tables. See the [review workflow](../parity-audit/README.md).

Native roots and syntax-discovery limits are explicit in the ledger/tool docs.
The gate establishes consistency of the discovered source inventory and its
reviews, rather than completeness for arbitrary Rust constructs. Library builds,
C export/header checks and behavior tests remain separate release requirements.
Supported declarations do not imply identical argument domains, enum layouts,
ownership or platform execution. Partial projections and intentional exclusions
are reviewed outcomes; runtime and performance evidence remain separate.
Startup configuration and [runtime applicability](runtime-configuration.md)
have distinct activation boundaries.

Signature dependencies include recursively exposed local types and members.
The ledger distinguishes excluded native driver/session representations and Rust
utilities from value projections whose exact boundary evidence remains pending.
Pending entries enforce declaration review and do not establish value parity.
